# Дополнительные правила шагов

## Предусловия

В `Given` описывайте состояние перед проверяемым действием.
Действия, которыми получено это состояние, описывайте только тогда, когда его можно получить несколькими путями и для теста важен конкретный путь.

Для проверки отмены оплаченного заказа достаточно состояния:

```gherkin
Given заказ оплачен
```

Создание заказа и его оплату не нужно описывать отдельными действиями, если для проверки отмены неважно, как заказ стал оплаченным.

## Действия

### Одно действие

Обычно сценарий проверяет реакцию на одно действие или событие, описанное в `When`.
В `When` должно быть понятно, какое действие или событие вызывает проверяемую реакцию системы.
Например: `When покупатель отменяет заказ`, `When истекает срок приглашения` или `When список сортируется`.
Дополнительные условия и результаты продолжайте через `And`.

```gherkin
Given заказ оплачен
And заказ ещё не отправлен
When покупатель отменяет заказ
Then заказ отменён
And оплата возвращена
```

Здесь `And` продолжает предыдущий тип шага: сначала предусловия, затем результаты.

### Последовательность действий

Описывайте несколько действий, если проверка зависит от их последовательности.
Первое действие помещайте в `When`, последующие — в отдельные `And`.

Например, для проверки повторной отмены нужны обе попытки:

```gherkin
Given заказ можно отменить
When покупатель отменяет заказ
And покупатель повторно отменяет заказ
Then повторная отмена отклоняется
```

### Чтение состояния внутри проверки

Чтение состояния можно выполнять внутри шага проверки результата через публичную операцию.
Если способ чтения несущественен для сценария, описывайте только ожидаемый результат:

```gherkin
Given заказ ожидает оплаты
When покупатель оплачивает заказ
Then оплата подтверждается
And покупатель видит заказ оплаченным
```

Реализация последнего шага читает состояние заказа и проверяет его.
Здесь `And` продолжает проверку результатов.

### Явное чтение состояния

Если чтение нужно описать явно, используйте отдельный `When`, а его результат проверяйте в следующем `Then`:

```gherkin
Given заказ ожидает оплаты
When покупатель оплачивает заказ
Then оплата подтверждается
When покупатель запрашивает состояние заказа
Then заказ имеет состояние «оплачен»
```

Для нескольких явных операций чтения повторяйте пару `When` и `Then` для каждой операции.
`And` продолжает предыдущий тип шага; новое действие после проверки результата начинайте с `When`.

## Проверки результата

В негативном сценарии явно проверяйте отсутствие побочного эффекта, если оно требуется контрактом.
Не сопровождайте положительный результат зеркальным утверждением об отсутствии альтернативного результата, если это отсутствие не является отдельным требованием контракта.

Если при отказе в заказе товар не должен резервироваться:

```gherkin
Given товара недостаточно для заказа
When покупатель оформляет заказ
Then оформление отклоняется
And товар не резервируется
```
