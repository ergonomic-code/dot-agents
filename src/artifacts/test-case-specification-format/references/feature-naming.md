# Именование Feature

Именуйте `Feature` как `<человекочитаемый проверяемый объект> (<SUT reference>)`.
Используйте подтверждённую доказательствами SUT-ссылку и не придумывайте её.
Если SUT-ссылку нельзя установить, остановитесь и сообщите об отсутствующей точке привязки.
Выводите SUT-ссылку HTTP-границы как `<HTTP method> <path>`.
Для другой границы используйте её устойчивый внешний идентификатор операции: например, команду, topic, имя очереди, маршрут, команду CLI или внешнюю операцию.
Выводите SUT-ссылку компонента как `<ClassName>` для поведения всего класса или класса с одной публичной операцией, а как `<ClassName>.<methodName>` — для поведения, ограниченного одной из нескольких публичных операций.
Выводите SUT-ссылку unit-а как `<ClassName>` для поведения всего класса, как `<ClassName>.<methodName>` для поведения одного метода или как точное имя функции верхнего уровня из фактического кода или предоставленного дизайна.
Для поведения, относящегося к одному полиморфному варианту, добавляйте `, <exact variant reference>` внутри скобок SUT.
Не добавляйте SUT-ссылку, если точный суффикс в скобках уже есть.
Считайте материализованную SUT-ссылку обязательной точкой привязки к коду, а не случайной технической деталью для абстрагирования.
