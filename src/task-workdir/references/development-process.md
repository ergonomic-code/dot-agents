# Структурированный процесс разработки задачи

Это соглашение дополняет соглашение памяти задачи при подготовке решения и выборе инкрементов разработки.
Бриф решения, якори, описание API, тестовые кейсы и дизайн реализации создавай в зависимости от потребностей конкретной задачи.

## Коды дополнительных файлов

Используй префиксы для артефактов структурированного процесса разработки:

- 010 — постановка задачи.
  Требования в краткой форме, дополнительные ресурсы с примерами, наборы данных и подобные входные материалы.
- 020 — описание текущего состояния.
  Артефакты, описывающие текущее состояние: текущий API, текущие тестовые кейсы, текущую архитектуру и подобный контекст.
- 030 — описание целевого состояния.
  Артефакты, описывающие целевое решение: бриф, API, тест кейсы, архитектура, дизайн и т.п.
- 040 — рабочие файлы реализации.

## Артефакты разработки

- `030-solution-brief.md` — технические и процессные рамки решения задачи: выбранный подход, требования и ограничения реализации, этапы выполнения при их наличии.
- `020-code-anchors.md` — ссылки на относящиеся к задаче исходный код, примеры и тесты.
- `020-api-current.md` — текущий REST API в формате `humanistic-api/v1`.
- `020-test-cases-current.md` — существующие относящиеся к задаче тестовые кейсы.
- `030-api-new.adoc` — целевой REST API.
- `030-test-cases-new.md` — новые тестовые кейсы.
- `030-implementation-design.md` — текущий накопленный дизайн решения.
  Перед созданием или обновлением прочитай `framework_checkout_root/src/task-workdir/references/implementation-design-template.md` и следуй его структуре и правилам.

## Порядок работы

Подготовку требований, исследование кода и выбор решения выполняй через `$prepare-development-task`, если запрошена такая подготовка.
Для выбора очередного инкремента используй `$select-next-increment`.
Он различает поведение, требующее теста, и работу без новых тестов.
Детали дизайна добавляй по мере необходимости выбранного инкремента.

## Привязки операций

При наличии активной задачи передавай применимому скиллу или операции относящиеся к ней привязки:

- `030-solution-brief.md` — требования к решению;
- `030-implementation-design.md` — дизайн решения;
- `020-code-anchors.md` — якори в коде;
- `020-api-current.*` — описание текущего API;
- `030-api-new.*` — описание либо контракт целевого API;
- `020-test-cases-current.md` — существующие релевантные кейсы;
- `030-test-cases-new.md` — новые спроектированные кейсы.

Передавай существующее содержимое или конкретный разрешённый путь результата напрямую.
Отсутствие необязательного артефакта само по себе не блокирует работу.
