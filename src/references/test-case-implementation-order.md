# Порядок реализации тест кейсов

Применяй эти правила при выборе новых поведенческих кейсов для реализации или определении их порядка.
Выбирай вид теста и SUT по `../conventions/core/test-case-selection.md`; приведённый ниже порядок не определяет уровень тестирования.

- Среди нереализованных успешных сценариев сначала выбирай допустимый по контракту вырожденный кейс с минимальным объёмом поведения производственного кода.
  - Предпочитай кейс, требующий наименьшего числа правил, источников данных, переходов состояний и ветвлений.
- Если допустимого по контракту вырожденного кейса нет, выбирай самый узкий полный успешный сценарий.
- В последующих инкрементах расширяй работающее поведение на одно обязательство или по одному измерению поведения за раз.
- После первого успешного сценария реализуй расширения, касающиеся валидации, авторизации, контроля доступа, отсутствующих ресурсов, доменных и инфраструктурных ошибок, а также прочие расширения.
- Определяй порядок последующих инкрементов по брифам, необходимости для поведения и размеру изменения.
- Не объединяй независимые варианты, кроме одного полного параметризованного набора, разрешённого правилами тест кейсов.
