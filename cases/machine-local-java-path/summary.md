# Локальный путь Java в переиспользуемых файлах

## Свидетельства

Сессия: `01a0f77b-9147-7f00-8b66-0f86af977702`.
При доработке инструмента измерения Gradle агент прочитал машинные инструкции и проектное требование определять `JAVA_HOME` из локальных источников.
Затем он сохранил абсолютный путь своей машины в fallback скрипта, примере запуска скилла и командах отчёта.
Обезличенный фрагмент патча:

```diff
-DEFAULT_JAVA_HOME_PATH="${JAVA_HOME:-/home/local-user/jdks/21}"
+DEFAULT_JAVA_HOME_PATH="${JAVA_HOME:-/home/local-user/jdks/25}"
```

Путь уже был зашит в скрипт; агент заменил его на другой локальный путь вместо устранения привязки к машине.
В сессии также зафиксировано чтение бейзлайна, проектного контекста, скилла измерений, `skill-creator`, а позднее индексов и соглашений разметки, кода и тестов.
Указание использовать локальные настройки для запуска не запрещало сохранять полученный путь в переиспользуемые файлы.
В проверенных файлах фреймворка отдельного правила переносимости не найдено: подтверждён пробел в контексте.
Влияние привычного fallback на решение агента — гипотеза, а не установленная причина.

## Исправление

Добавлены небольшое соглашение о переносимых путях и тематический индекс модуля `core`.
Пути для других машин задаются относительно определённого корня либо через настройки; при отсутствии источника пути агент запрашивает конфигурацию.
Фактические пути в отчётах и логах разрешены, но их переиспользуемые команды должны быть переносимыми.
Маршрутизация остаётся в индексе, а правило не зависит от Java, Gradle или структуры задачи.
README синхронизирован с новой возможностью `core`.

## Проверка

`pytest -q`: 107 тестов прошли, включая структурные проверки соглашений, ссылок, метаданных маршрутизации и загрузчика.
Генератор `render_filtered_routes` из установленного в исходниках SessionStart hook с реальным `src/context` и набором `{core}` выдаёт маршрут `portable-paths.md`.
Прямой запуск hook из корня фреймворка остановился из-за отсутствия целевой установки `.agents/ergo`; полная интеграция в целевом проекте этим запуском не проверена.
`git diff --check` и ревью через `review-framework-changes` не выявили замечаний.
Изменение инструкций само по себе не доказывает соблюдение правила моделью; повторная проверка поведения в целевом проекте не выполнялась.
