# Содержание документации HTTP API

## Свидетельства

Сессия: `01a17637-1445-7882-aef5-1dff719c5d2c`.
Агент завершал реализацию получения списка объектов с фильтрацией и курсорной пагинацией.
Релевантные фрагменты исходного запроса пользователя:

```text
Заверши задачу

Синхронизируй OpenAPI, JSON Schema, типизированные HTTP-хелперы и humanistic-api/v1. Устрани устаревшие записи todo.md и work-state.md, сохрани подтверждённые решения и фактические результаты проверок.

Проверь документацию соответствующими валидаторами, включая $validate-openapi, и выполни git diff --check.
```

При обновлении OpenAPI агент включил в описание эндпоинта сведения об источнике данных, временном состоянии прототипа и поведении курсора при исчезновении граничного объекта.
Обезличенный фрагмент добавленного текста:

```yaml
description: |
  Оборудование, специалисты, диапазоны и границы просмотра используют временное состояние прототипа.
  Исчезновение граничного объекта не делает курсор недействительным; снимок списка не фиксируется.
```

Пользователь указал, что документация должна кратко описывать назначение, функцию и прежде всего использование эндпоинта, исключать детали реализации и незначительные подробности.
Дополнительные пояснения нужны только для вероятных ошибок использования либо ошибок с высоким ущербом и трудноустранимыми последствиями.
При уточнении правила пользователь подчеркнул:

```text
в документации метода надо кратко объяснять как и для чего его использовать на семантическом уровне.
А в тривиальных случаях - даже это не надо объяснять
```

## Причина

Подтверждён пробел в контексте.
В сессии прочитаны HTTP-индекс, проектные соглашения API и синхронизации OpenAPI, контракт задачи и правила оформления разметки.
Они задавали синхронизацию документации с внешним контрактом, но не ограничивали содержание пояснительного текста его пользой для потребителя API.
HTTP-индекс не содержал маршрута к правилам написания документации API.
Мотив переноса этих подробностей в OpenAPI достоверно не установлен.

## Исправление

Выбран оптимальный вариант.
Соглашение `src/conventions/http-api/api-documentation.md` задаёт краткое описание семантики использования метода с пропуском пояснения в тривиальных случаях, исключает пересказ формального контракта, детали реализации и незначительные подробности, ограничивает дополнительные пояснения риском ошибок использования.
Оно сохраняет полноту формального HTTP-контракта.
Индекс `src/context/http-api.md` явно охватывает документацию и загружает соглашение при её написании или изменении, включая OpenAPI.
Правило относится к документации HTTP API независимо от формата и не расширяется на всю документацию проекта.
