# Фикстура одного метода как часть Given

## Свидетельства

Сессия: `01a177d6-1073-7262-8738-0bdc08f61159`.
Исходный запрос касался расширения существующего поведения новым вариантом входных данных.
Описание задачи обезличено; ниже сохранены только релевантные запросы о работе с тестами.

Позднее пользователь запросил реализацию:

> Сделай задачу до конца по ТДД с коммитом на каждый шаг.
> Для начала сделай необходимый минимум тестов и напиши список тестов, которые ты ещё предлагаешь написать

После появления дублирующих тестов пользователь уточнил:

> ок, теперь возвращаемся к тестам.
> чёт выглядит так, что ты велосипеод придумал, вместо того, чтобы дополнить существующие тесты новым вариантом данных. если это так - исправься

Агент заменил отдельный тест вариантом данных существующего параметризованного метода.
Источник параметров одного метода он добавил в отдельный файл фикстур и подключил через внешний `@MethodSource`.
Создание и использование функции подтверждаются применённым патчем и результатом коммита в сессии.
Обезличенный фрагмент структуры после правки:

```kotlin
// Файл класса кейса
@MethodSource("example.fixtures.CasesKt#testCases")
fun test_behavior(input: Input, result: Result) { /* Given, When, Then */ }

// Отдельный файл fixtures/Cases.kt
fun testCases(): Stream<Arguments> {
    val first = firstInput()
    val second = secondInput()
    return Stream.of(
        Arguments.of(first, resultFor(first)),
        Arguments.of(second, resultFor(second)),
    )
}
```

При разборе пользователь указал, что фикстуру одного метода следовало оставить в том же классе как часть Given, на которую правило выноса хелперов не распространяется.

## Причина и ожидаемое поведение

Агент загрузил `src/context/tests.md`, соглашения `test-design.md`, `test-fixture-architecture.md`, `test-implementation.md` и чек-лист реализации тестов.
Пути соглашений без префикса здесь относятся к `src/conventions/core/`.
В результате чтения `test-design.md` присутствуют оба категоричных требования: выносить «весь код фикстур» и оставлять в файлах классов «только кейсы».
Подтверждённая причина — конфликт указаний: запрет охватывал и специфичную для кейса подготовку, которую соглашение реализации относит к `Given`.
Свидетельств пропуска маршрутизации нет; прямое объяснение агентом мотива переноса в сессии отсутствует.

Данные и подготовка фикстуры одного метода, включая источник его параметров, должны оставаться в классе кейса как часть `Given`.
Низкоуровневые и переиспользуемые хелперы по-прежнему выносятся из файла класса.

## Выбранное исправление

Выбран оптимальный вариант: уточнение границы в `src/conventions/core/test-design.md` и согласование проверки в `src/conventions/core/test-implementation-checklist.md`.
Дизайн тестов уже определяет размещение фикстур и хелперов; отдельное технологическое соглашение для источников параметров не требуется.
Оба файла подключены из `src/context/tests.md`, поэтому маршрутизация не меняется.
Код целевого проекта в рамках исправления фреймворка не изменяется.
