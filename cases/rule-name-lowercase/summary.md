# Имя Rule со строчной буквы

## Свидетельства

Сессия: `01a12f65-d824-7b70-99d3-59910a29805a`.
Пользователь запросил проектирование тест-кейса:

```text
371-1

/$design-test-case

Кейс на неизменность нескольких ролей при изменении имени
```

Агент сформировал спецификацию проверки сохранения ролей при изменении имени пользователя.
Имя правила начиналось с заглавной буквы:

```gherkin
Rule: При изменении имени пользователя метод должен сохранять точный набор его ролей
```

Ожидаемое имя начинается со строчной буквы:

```gherkin
Rule: при изменении имени пользователя метод должен сохранять точный набор его ролей
```

## Причина

Подтверждён пробел в контексте: загруженные требования формата определяли форму обязанности, но не регистр начала имени `Rule`.
Сессия подтверждает загрузку `design-test-case`, `write-verification-check`, `test-case-specification-format/ARTIFACT.md`, справочников `layout.md`, `mode-full.md`, `feature-naming.md`, `full-mode-checklist.md`, `requirements-coverage-checklist.md` и соглашения `core/test-naming.md`.
Наблюдаемая ошибка не вызвана отсутствием загрузки формата.

## Исправление

Выбран оптимальный вариант: требование строчной буквы добавлено в `src/artifacts/test-case-specification-format/ARTIFACT.md`, а проверка — в `references/full-mode-checklist.md` этого артефакта.
Правило применяется к обоим режимам формата; финальная проверка полного режима доступна через существующий `write-verification-check`.
Новый справочник и изменения маршрутизации не нужны.
Добавление одной строки в файл длиннее 50 строк оправдано тем, что описание артефакта уже содержит общие требования к форме `Rule`.
