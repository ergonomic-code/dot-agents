## Problem

При документировании текущего перманентного удаления пользователя агент допустил несколько последовательных ошибок:

- Сначала создал PlantUML вместо диаграммы `structure-chart-v1`.
- После уточнения вынес диаграмму в отдельный `.mmd`, хотя пользователь просил добавить её в раздел конкретного Markdown-файла и затем был вынужден заинлайнить её сам.
- Показал концептуальные узлы планировщика, баз данных, данных профиля, каталога и OBS вместо фактического дерева вызываемых методов.
- Добавил на рёбра входные и выходные данные, цикл и порядок выполнения, хотя пользователь этого не просил.
- Указал отсутствующий в проверенной текущей реализации `versionId`, опираясь на устаревший контекст до полной проверки исходного кода.
- Добавил текстовое описание примерно втрое подробнее требуемого уровня.

Текущий контракт `structure-chart-v1` разрешает указывать условия и передаваемые данные, когда они уточняют взаимодействие, но не задаёт безопасное поведение по умолчанию.
В нём также нет явного правила для диаграммы дерева методов: показывать только реально существующие методы целевого кода и останавливать раскрытие на вызове библиотечного метода.
Из-за этого агент может подменить запрошенное дерево вызовов компонентной схемой и перегрузить диаграмму деталями потока выполнения.

## Target behavior

- Явно заданное пользователем место диаграммы имеет приоритет: при запросе инлайн-диаграммы Mermaid остаётся в указанном документе.
- Для дерева вызовов узлами служат только реально существующие методы, подтверждённые текущим исходным кодом.
- Вызванный библиотечный метод может быть листом дерева, но его внутреннее устройство не раскрывается.
- Входные данные, выходные данные, циклы, условия, нумерация шагов и иной поток управления по умолчанию не добавляются.
- Такие детали добавляются только по явному запросу пользователя или когда без них невозможно различить смысл взаимодействий.
- Концептуальные компоненты, хранилища и последствия выполнения не подменяют методы на диаграмме дерева вызовов.
- Утверждения о текущей реализации проверяются по актуальному коду, а не переносятся из памяти или проектного замысла.
- Сопроводительный текст фиксирует только существенное поведение, которое не видно из диаграммы, и остаётся кратким.

## Проверяемый результат

Для запроса на диаграмму текущего дерева вызовов результат содержит корневой метод и непосредственно вызываемые им методы без узлов баз данных, хранилищ и планировщика.
Если пользователь отдельно не запросил данные или поток управления, рёбра не содержат `in`, `out`, `loop`, условий или порядковых номеров.
Если вызов уходит в библиотечный API, диаграмма заканчивается на реально вызванном методе.
Если рядом требуется описание последствий, оно не дублирует дерево и кратко описывает только наблюдаемое поведение и ограничения.
